Verification: `MetalAdoptionPolicy` unit tests in Tests/LogosTests/SwiftTermViewMetalTests.swift assert the enable is attempted when window-attached and skipped before window attachment; real engagement (`isUsingMetalRenderer == true`) is confirmed interactively in task 3.1 because the SwiftTerm TerminalView cannot be instantiated in `swift test` (SIGSEGV). Implements design decision: D1: Adopt the fork's Metal renderer rather than hand-roll.
- [x] 1.2 Terminal falls back to CoreGraphics when Metal is unavailable: the enable action runs through `MetalAdoptionPolicy`, which catches a throwing enable (the fork's `setUseMetal` throws when no Metal device exists) so unsupported hardware stays on today's CoreGraphics path with no crash, logged not surfaced. Verification: a `MetalAdoptionPolicy` unit test injects a throwing enable and asserts the policy returns false (stayed on CoreGraphics), marks the attempt consumed (no retry loop), and does not rethrow. Implements design decision: D4: CoreGraphics fallback preserves "never worse than today".
