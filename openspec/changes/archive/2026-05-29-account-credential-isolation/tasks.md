## 2. Per-account isolated config directory

- [x] 2.1 `Account` exposes a stable per-account claude config directory `configDirPath` (derived from `homeDirectoryPath`, e.g. `<homeDirectoryPath>/.claude`) so that each account spawns claude with an isolated config directory and two distinct accounts produce two distinct values. Verification: a test in `Tests/LogosTests/AccountCredentialIsolationTests.swift` asserts two distinct accounts yield distinct, non-empty `configDirPath`. Implements design decision: D1: Per-account `CLAUDE_CONFIG_DIR` isolation (chosen).
- [x] 2.2 `ClaudeProcessConfig` for an account-scoped spawn emits `environment["CLAUDE_CONFIG_DIR"] = account.configDirPath` and `environment["CLAUDE_SECURESTORAGE_CONFIG_DIR"] = account.configDirPath` (same path — the latter is the variable that actually keys the Keychain service name), and never passes `CLAUDE_SECURESTORAGE_CONFIG_DIR` as an empty string (an empty value collapses to the bare service name and defeats isolation; any inherited empty value is overwritten or removed). Verification: a test asserts the emitted environment carries a non-empty `CLAUDE_CONFIG_DIR` and a non-empty `CLAUDE_SECURESTORAGE_CONFIG_DIR` both equal to `configDirPath`, and contains no empty `CLAUDE_SECURESTORAGE_CONFIG_DIR`. Implements design decision: D1: Per-account `CLAUDE_CONFIG_DIR` isolation (chosen).

## 3. Remove the shared-entry swap

- [x] 3.1 `AccountManager.setActive(_:)` and `remove(accountId:)` stop touching the system Keychain so that account switching performs no system Keychain write and the shared bare Keychain entry is never mutated; switching updates only local active-state and the persisted account list. Verification: a test injects a `SystemKeychainBridge` test double that fails if `write`/`delete` is invoked, exercises `setActive`/`remove`, and asserts zero invocations. Implements design decision: D1: Per-account `CLAUDE_CONFIG_DIR` isolation (chosen).
- [x] 3.2 Retire the dialog-triggering credential mutation: remove `write`/`delete` from the production conformer `RealSystemKeychainBridge`, slim the `SystemKeychainBridge` protocol to read-only (retained only if migration's capture-read needs it, otherwise removed), and update the in-memory test double to match. Verification: the project compiles with the slimmed protocol and full `swift test` stays green; a test confirms `RealSystemKeychainBridge` no longer exposes a credential-write path. Implements design decision: D2: Retire `SystemKeychainBridge`'s write/delete path.

## 4. Needs-reauth state and non-destructive migration

- [x] 4.1 An account whose per-config-dir credential does not yet exist is shown in a needs-reauth state in the switcher — a missing per-account credential is surfaced as needs-reauth — directing the user to authenticate via `claude login` under that account's config directory instead of spawning a silently unauthenticated session. needs-reauth is computed from promptless signals only (no system Keychain read): an account counts as authenticated when EITHER Logos's own per-account authenticated flag is set OR a `.credentials.json` file exists in its config directory; needs-reauth requires both to be absent. Verification: a test asserts an account with neither signal is reported needs-reauth, an account with the flag set is not, and an account with a `.credentials.json` file present is not — with no system Keychain read performed; a manual check confirms the switcher shows the indicator. Implements design decision: D3: Onboarding/(re)auth via `claude login` under the account's config dir.
- [x] 4.2 On first launch of the new build, existing accounts migrate non-destructively: each account's config dir is ensured to exist with no credentials written, each account lacking a promptless credential signal (no `.credentials.json` file) is marked needs-reauth, and the bare `Claude Code-credentials` entry is left byte-identical so plain-terminal `claude` keeps working. Verification: a test asserts migration marks accounts needs-reauth, performs zero credential writes (asserted via the zero-interaction system-bridge double), and ensures each config dir exists. Implements design decision: D4: Non-destructive migration.
